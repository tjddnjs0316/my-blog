프로그래밍을 배우기 시작한 지 1주일이 지났다. 제목을 "생존일지"라고 붙인 이유는, 이번 주는 뭔가를 잘했다기보다 낯선 도구들 사이에서 안 죽고 버틴 느낌이 더 컸기 때문이다.
1주차에는 크게 세 가지를 했다: **Git/GitHub 환경 구축**, **Sourcetree 사용법**, 그리고 **VS Code(에디터) 환경 구축**. 오늘은 이 셋을 놓고 뭘 얻었고 뭐가 아직 부족한지 정리해본다.

## 이번 주 한 일 한눈에 보기

| 항목 | 한 일 |
|---|---|
| Git/GitHub 환경 구축 | 로컬 저장소 만들기, add/commit/push 흐름 익히기, 블로그 만들어서 배포까지 해봄 |
| Sourcetree 사용법 | 버튼 클릭으로 커밋/푸시/브랜치 작업하는 법 익힘 |
| VS Code 환경 구축 | 확장 프로그램 설치, 터미널에서 git 연동, 테마·폰트 설정 |

## Git/GitHub — 아직 헷갈리는 것

`git init`으로 저장소를 만들고, `git add` → `git commit` → `git push` 순서로 GitHub에 올리는 흐름 자체는 반복하면서 눈에 익었다. 브랜치(branch, 원래 작업 흐름에서 갈라져 나온 실험용 줄기)를 만들어서 merge(합치기)하는 것도 한 번씩은 해봤다.

그런데 여전히 헷갈리는 이유를 스스로 생각해봤는데, **"명령어를 직접 타이핑해야 한다"**는 점이 컸다. Sourcetree에서는 버튼 하나 누르면 끝나는 작업인데, 터미널에서는 그 버튼 뒤에 숨어있던 명령어(예: `git commit -m "메시지"`)를 내가 직접 정확히 쳐야 하니까 오타나 순서를 헷갈릴 여지가 더 많다고 느꼈다.

```
git add .
git commit -m "메시지"
git push
```

## Sourcetree — 자신 있게 된 것

Sourcetree는 커밋, 푸시, 브랜치 만들기 같은 작업을 버튼 클릭으로 처리한다. 화면에 변경된 파일 목록이 바로 보이고, 스테이징(커밋에 담을 파일 고르기)도 체크박스로 고르면 돼서 실수할 여지가 적었다.

다음 단계로는, Sourcetree에서 버튼을 누르기 전에 어떤 git 명령어가 실행되는지 확인해보기로 했다. 버튼과 명령어를 1:1로 연결해서 외우면, 터미널에서 직접 칠 때도 덜 헷갈릴 것 같다.

| | Sourcetree | 터미널(Git 명령어) |
|---|---|---|
| 실행 방식 | 버튼 클릭 | 명령어 직접 입력 |
| 장점 | 변경 파일이 한눈에 보임, 실수 적음 | 어떤 프로젝트에서도 바로 쓸 수 있음(도구 의존 없음) |
| 단점 | 뒤에서 무슨 명령어가 실행되는지 안 보임 | 명령어와 옵션을 외워야 함 |

## VS Code — 환경 구축한 것

VS Code는 이번에 처음 제대로 설정해봤다.

- 확장 프로그램(extension) 설치: 필요한 기능을 추가로 깔아서 에디터를 내 상황에 맞게 확장함
- 터미널에서 git 연동: VS Code 안의 터미널에서 바로 git 명령어를 칠 수 있게 확인함
- 테마·폰트 설정: 오래 봐도 눈이 덜 피곤하도록 색상과 글꼴 크기를 조정함

## STAR로 이번 주 정리해보기

| 단계 | 의미 | 이번 주에 적용해보면 |
|---|---|---|
| **S**ituation (상황) | 어떤 상황이었나 | 프로그래밍을 막 시작해서, 작업 도구(Git/GitHub, Sourcetree, VS Code) 환경조차 없던 상황 |
| **T**ask (과제) | 해결해야 했던 문제 | 커밋/버전 관리 흐름을 이해하고, 손에 익은 개발 환경을 갖추는 것 |
| **A**ction (행동) | 실제로 한 행동 | Sourcetree로 버튼 조작 먼저 익히고, 병행해서 git 명령어를 직접 쳐봄. VS Code에 확장 프로그램·터미널 연동·테마를 설정함 |
| **R**esult (결과) | 그래서 어떻게 됐나 | Sourcetree는 혼자서도 다룰 수 있게 됨. git 명령어는 아직 손에 덜 익어서 다음 목표로 남음 |

## 더 학습하면 좋은 개념

- **git 명령어와 Sourcetree 버튼 매핑** — Sourcetree 버튼이 어떤 명령어를 대신 실행하는지 알면, 나중에 Sourcetree가 없는 환경(예: 서버, CI)에서도 똑같이 작업할 수 있다.
- **.gitignore** — 프로젝트에 있는 모든 파일을 다 커밋할 필요는 없다. 어떤 파일을 git이 무시하게 할지 아는 건 저장소를 깔끔하게 유지하는 데 필수다.
- **브랜치 전략(branching strategy)** — 지금은 브랜치를 한두 개만 써봤지만, 협업을 하게 되면 언제 브랜치를 나누고 언제 합칠지에 대한 팀 규칙이 필요해진다.
- **VS Code 단축키와 설정 동기화(Settings Sync)** — 지금 어렵게 맞춘 확장 프로그램·테마 설정을 다른 컴퓨터에서도 그대로 쓸 수 있게 해주는 기능으로, 알아두면 편하다.
